# Interrupted initial-exec notifications

Canonical31ac passed its original ten-workflow cohort. A fresh PR observer run44492652035 subsequently failed native ARM64 full-guarded policy initialization: SIGKILL before fixture cleanup, complete zero-byte stderr, with all five source/native/helper hashes equal to the earlier passing31ac run. AMD64 passed. Original artifacts and logs remain retained; no unchanged native retry was used to obtain green.

The helper explicitly killed itself on broker receive/validation/send errors. [The kernel contract](https://docs.kernel.org/userspace-api/seccomp_filter.html#userspace-notification) permits notification withdrawal on signals and requires receive ENOENT to wait again. Stale response IDs can also disappear before a reply. The original kill lacks a syscall-phase diagnostic, so its exact branch, external kill or OOM attribution cannot be proved from exit status alone.

A same-package ordering barrier pauses the actual broker after receiving a live notification. The parent signals only the owned exec thread with SIGURG, verifies that the kernel now rejects the original ID with ENOENT, then releases the broker. Parent decision logic with this scheduling seam reproduces a pre-exec SIGKILL and empty stderr. Removing the private seam restores the parent production file byte-for-byte; this is an instrumented ordering control, not execution of the unchanged original binary. Production Run always supplies a nil hook; no production command or environment enables it.

The corrected broker waits again on interrupted/withdrawn notifications, revalidates each live replacement against the exact original TID, architecture, execveat, verified executable descriptor and flags, and remains available until successful exec kills helper threads and closes the sole CLOEXEC listener. Other failures still fail closed, with only fixed phase/numeric errno diagnostics. One fixed retry message is emitted at most once per helper. A returned initial-exec error is marked before listener teardown so it retains its own error instead of becoming a broker kill.

The complete executable digest/ABI checks and BPF/listener setup are byte-identical to31ac. Existing caller policies, native RPC/cleanup deadlines and dependency graph are unchanged. Tests keep JSON stdout separate from fixed stderr diagnostics. A verified but truncated ELF additionally checks the initial-exec failure path.

Go1.27.4 builds and vet pass for Linux ARM64 and AMD64. The full nativeobserve package executes on an ARM64 Linux DockerVM, with the original network/process/message/addressed-IO/filter-replacement/same-executable/reexec denials, thread/Unix-pair support, same PID, listener cleanup, reference privacy/immutability and digest-refusal controls passing without skips. The interrupted case verifies successful replacement execution, all existing denials and exactly one bounded retry diagnostic. Docker runs with UID1000, no capabilities, no network, read-only root and bounded tmpfs; its outer seccomp profile is disabled to assess the product filter alone. CGO is disabled for this local kernel control; AMD64 execution and native race/Codex startup qualification remain separate.

These controls reproduce and repair a broker error-handling mechanism. They do not establish the exact historical SIGKILL branch, authenticated coding recovery, a Windows runtime repair, main readiness or release acceptance.
