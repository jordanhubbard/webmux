# Scoped MAC project collection

Component qualification for [#674](https://github.com/jordanhubbard/webmux/issues/674),
stacked on #679. Read the [contract](../../mac-project-view.md) and
[receipt](receipt.json). The original `receipt.json` records the earlier collector-only checkpoint and its
source hashes. `runtime-read.json` records the subsequent private runtime loader,
shared browser/agent reader, MCP tool, UI and standalone admission guard. These
receipts retain their separate evidence scope; neither completes live fleet
project enrollment, roadmap linkage or conflict/order qualification.

The reader independently verifies every returned task, withholds foreign and
unresolved dependency details, preserves bounds/unknown states, and discards the
whole observation if credentials are refused. Titles and reported priority come
from the verified task response. Four pipelines collect at most eight candidates
under one ten-second budget. No cache supplies authorization.

Package race tests and vet pass. Deliberate Go overlays remove endpoint scope
checks or final authentication; the corresponding privacy/revocation controls
fail. Those overlays do not modify real source and are not historical defects.
Windows AMD64 test cross-compilation passes; native execution is not implied.

The dedicated local read-only MAC client collected two actual tasks from the
explicit user-supplied fleet context. Incomplete coverage and unknown conflict/
ordering verdicts were preserved. The publisher fingerprint matched its earlier
qualification. Raw task data, project key and backlog counts remain private;
the public receipt retains selected qualification metadata and a projection digest.
This is not a WebMux project enrollment or human/agent product acceptance.
No task, worker, credential, profile, service, policy or NAS state changed.
