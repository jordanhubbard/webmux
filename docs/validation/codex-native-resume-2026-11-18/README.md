# Native Codex continuation through the launch wrapper

The wrapper/policy source bindings below remain unchanged. The
[later creation-factory checkpoint](../codex-native-create-2026-11-18/README.md)
adds internal Go embedding and durable launch composition; the unembedded
descriptions below record the state when this recovery evidence was captured.

Rig's managed resume uses an explicit native UUID, its `-m` model alias and a
shell working directory rather than a `-C` argument. The original fresh-only
wrapper refused that shape. The transformer now accepts one explicit UUID and
matching model alias, checks every supplied policy field, and pins the frozen
project/model/effort/tier before the resume subcommand. It rejects names,
pickers, `--last`, prompts, forks, duplicate targets and policy drift. UUID
validation supplies no recovery authority; the manager/caller must verify the
original conversation and immutable selected occupant.

The [source-bound receipt](receipt.json) records three actual authenticated
Codex0.169/Rig0.7.18/Node24 cases on macOS ARM64 using these exact modules and
existing native authentication without copying credentials. Workspace policies
come from documented native per-thread overrides, not selected/default owner
workspace-profile qualification.

For network=true and false, each fixture:

1. Creates an actual native managed Codex seat and a terminal sibling, then
   verifies fresh challenge/tool output and exact native sandbox/roots.
2. Captures a native snapshot naming the original conversation. It removes the
   challenge source, kills only its own verified Codex process and proves loss.
3. Uses checked Stop for the original idle occupant, then the supported single
   node launch endpoint with that exact snapshot. This leaves non-targets
   unchanged and starts one resumed provider.
4. Gets a remembered challenge answer in the original conversation without
   tools. The original native log path retains its entire prior byte prefix and
   appends new records. A fresh challenge and actual sandbox writes verify the
   policy again after recovery: two allowed writes and five `EPERM` attempts
   against existing forbidden directories, including `.git` and generated roots.
5. Replays the original creation operation without another provider launch,
   checks the selected restored process stops through native checked Stop, and
   confirms sibling survival and private daemon/tmux cleanup.

The network-disabled case additionally repeats the same native recovery POST
twice. Both report the already-running seat and start nothing. Coordinator
reachability follows the owner's network choice: offline/partial with networking
disabled, full node identity/roster with it enabled.

The missing-conversation case records a deliberately unused native UUID through
Rig's supported operator CLI and captures it in a snapshot. Native recovery
returns HTTP409 `awaiting-decision`, rolls back the failed resume, and creates no
fresh replacement conversation. The original history and sibling survive. This
is a missing-ID control, not physical native-storage corruption/deletion.

Whole-rig restore correctly refuses an active sibling (`rig_not_stopped`). The
native account-restart preview also refuses unverified process settings on this
macOS host; its process-home/cwd observer reads Linux `/proc`. These are retained
refusals. The qualified path uses single-seat snapshot launch instead of taking
the rig down or bypassing a native check.

All 168 local helpers, ten launch controls, five strict TypeScript projects,
272 installed lock identities and whitespace pass. Native evidence relies on
correlated tool records, policy contexts, OS process checks and original log
bytes, not model-only claims or screenshots.

The wrapper remains unactivated in WebMux. Caller/UI conversion, durable
manifest/original-intent publication, owner authorization, manager verification
and observation revalidation still must compose with #504/#508. This is native
provider-process-loss evidence; manager/host loss, reboot, selected profiles,
Linux/Windows and actual WebMux creation/recovery UI remain open. No adopted
seat gains lifecycle authority, and #438/#318 remain incomplete.
