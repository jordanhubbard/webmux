# Native Codex recovery conversation capture

A later [public original-operation recovery qualification](../codex-public-recovery-2026-11-18/README.md)
now covers the broker/UI and actual controller restart/SIGKILL on macOS with the
default native owner policy. The historical results below keep their own source
bindings and limits.

The internal `native-recovery-observe` action now captures the original native
conversation for a WebMux-created local Codex seat. Actual Go/Chrome/native
qualification at the revision in [receipt.json](receipt.json) first creates the
seat through the public application and performs a fresh coding turn. A separate
private executable calls the actual embedded Go coordinator with the server's
viewer identity. It verifies the same native conversation as the correlated
native tool records, and a second call reuses the same snapshot.

Capture resolves only an existing native launch record in the caller's owner
namespace. It cannot call the creation factory. The original native registration,
verified running executable/digest, current session and structured tmux socket
must match. Rig's generation-record endpoint is requested without `sinceBytes`,
so the response contains identity metadata without a transcript suffix. The
native file header, exact native home, inode/birth identity and project must join
that generation. Capture then verifies a native snapshot's original node,
wrapper, current history session and native conversation. Rechecking generation
and manager process identity rejects a change during capture.

The private durable reference contains the original snapshot/history/native
conversation and file identity, plus original launch-policy and snapshot hashes.
It contains no account credential or arbitrary environment values and grants no
Resume authority. The live proof also retains the public lost-reply/duplicate,
native owner environment/default policy and browser checked-Stop/sibling/viewer
controls from the [fresh public creation proof](../codex-public-native-2026-11-18/README.md).
The browser is private loopback auth-none; the native account is used in place.

Protocol controls refuse missing registration, unverified provider, foreign
header/inode/project, replaced wrapper, foreign snapshot conversation and a
changed generation. All 225 helper tests, five strict TypeScript projects,
affected Go race/vet and the Windows ARM64 cross-build pass locally.

This is an internal capture action exercised after real public coding, not
public broker retention, a public recovery button or a controller-crash/reboot
result. Public recovery integration remains open under #438/#194/#318, along
with restricted policies and authenticated Linux/broader Windows composition.
The original launch policy fingerprint is not proof of an unobserved later
interactive permission change. No full-roadmap or release-completion claim
follows from this result. Private drivers, raw receipt and native records are
retained by hash; model turns and account details are excluded here.


The separate [prepared recovery receipt](prepared-recovery.json) now qualifies
`native-resume` preparation at its own source revision. Two fresh Go invocations
bank and reread the exact reviewed original-only request with no native POST,
dispatch marker or recovery-environment handoff. After the preparing processes
have exited, an explicit completion is the first native POST. It retains the
original snapshot/history, conversation, revision, body and operation UUID.

That first response times out at the existing deadline; the ordinary duplicate
posts nothing. Immediate explicit inspection reports native operation-in-progress
and remains uncertain. Later inspections confirm already-running-original with
no native effect. The exact native conversation recalls the removed challenge
without tools; its file preserves its original prefix and appends new records.
Fresh tool results verify the owner environment/default full-access policy;
provider/sibling duplicate identity, selected Stop and private cleanup pass.
This is a private embedded-Go recovery composition after provider loss, not an
actual application crash or public recovery UI result.

Two earlier attempts were refused before dispatch because the Go controller's
PATH found Node 26 while a separate explicit version report checked Node 24.
Both remain excluded. The final fixture pins Node 24 in the original owner PATH
before environment capture and reports the actual controller runtime. No
supported-version or permission condition was relaxed. Runtime refusal is now
distinct from changed selection, launch, snapshot, review or request body. All
226 helper tests, including the unqualified-runtime no-query/no-handoff control,
and five strict TypeScript projects pass locally. The successful native proof
is separate from the public capture proof above and does not enable public
broker recovery by itself.

An actual exported-Go invocation on native Node 26.8.1 separately reports
`native_resume_runtime_unqualified` before calling Rig, creating native request
artifacts or honoring an input directory. Its receipt is bound in the prepared
recovery artifact. The final affected Go race suites/vet and Windows ARM64
cross-build pass with the prepared-dispatch implementation.
