# Native conversation recovery with the current owner environment

On 2026-11-18, the current environment-bearing Codex wrapper passed an actual
macOS native recovery composition at source `b9de5bf`. The private fixture uses
published Rig 0.7.18, native Codex 0.169.0, Node 24 and an existing native account
in place. It copies no authentication files and changes no owner permission policy.
Source and raw-artifact bindings are in [receipt.json](receipt.json).

After the creation helper was lost before its first handoff, the replacement
helper retained the original native enrollment and supplied its original owner
environment. A real coding turn established a fresh challenge, native Rig
identity, owner tools, environment and full-access policy. A native snapshot then
bound that exact conversation. The fixture removed the challenge file, killed
only its owned native Codex process, and used checked Stop for the selected idle
seat while preserving its sibling.

A private handoff bridge revalidated the original owner plan and environment
fingerprints and reopened the original private socket. Native single-node Resume
received the explicitly selected snapshot. Its HTTP response exceeded the
unchanged 10-second client deadline and remains recorded as uncertain. The
fixture did not repost that launch. Fresh-handoff acknowledgement and deliberate
read-only inspection found the original native node; native process arguments,
conversation history and new tool results established what actually resumed.

The resumed conversation recalled the removed challenge without a tool call.
The original native file retained its byte-identical prefix and appended new
records under the same conversation ID. A second fresh challenge and correlated
tool results verified the owner HOME, temporary directory, PATH, paired Rig CLI,
owner tool and inherited witness; manager-only state remained absent. The
original default full-access/never policy remained in force, with all four test
writes allowed. Two later deliberate duplicate Resume requests reported already
running and retained both the resumed provider PID and sibling PID. Checked Stop
ended only the selected provider; private daemon and tmux cleanup passed.

This establishes a private composition with the current wrapper, using a
prototype handoff bridge. It does not supply public WebMux recovery authority,
durable resume-dispatch deduplication after controller loss, public native-owned
creation/readiness/attachment, or a browser/controller-crash/reboot result. It
also does not qualify restricted policies or authenticated Linux or Windows.
Those acceptance items remain open under #438, #194 and #318. Linux startup and
isolation controls are documented [separately](../codex-linux-observation-2026-11-18/README.md).

exact prompt in either native event format and retains the no-tool requirement.
No response deadline or permission assertion was relaxed. Private raw receipts,
