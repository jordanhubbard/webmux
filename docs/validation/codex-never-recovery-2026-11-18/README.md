# Native recovery with never approval

The actual Go application and Chrome pass public original-conversation recovery
on macOS for native workspace-write/never and read-only/never Codex owners.
The clean executable reports source `d453528` and version 1.4.5. The
[receipt](receipt.json) binds its hash, 35 source files, native witnesses,
qualification drivers and retained failed attempts. This is a private loopback
auth-none browser using the existing native account in place; no authentication
files are read or copied by the qualifier.

| Owner policy | Approval in every native coding context | Allowed tool writes | Denied tool writes | Tool network |
| --- | --- | --- | --- | --- |
| Workspace-write | never | Project and configured extra root | Outside roots, .git, .codex, excluded owner TMPDIR | Denied |
| Read-only | never | None | All six targets | Denied |

Each case passes 16 browser/lifecycle controls through the current public
creation-request UUID endpoint: actual discarded native creation response,
explicit completion of the original selection after form edits, ordinary/ready
duplicates, fresh native coding, graceful controller restart with unchanged
provider, survivor reattachment without Resume, owned provider loss and explicit
checked Stop of its idle seat. The original native recovery request is then
banked and the real controller is SIGKILLed before dispatch. Reconstruction
retains uncertainty; ordinary duplicates post nothing, and deliberate completion
retains the same native UUID/body. The original conversation recalls the removed
challenge without tools and then repeats fresh policy/environment probes.
Viewer, sibling, retained native history and terminal-log prefixes, consumed
duplicates and final checked Stop all pass.

Native journals and immutable launch plans require `never` approval, the exact
owner model and sandbox on every coding turn. Fresh correlated tool results
before and after recovery verify allowed/denied writes and denied networking,
plus HOME/tmp/PATH, paired Rig/tool discovery and inherited values without
manager-only values. An unsandboxed connection independently proves that the
fixture's network endpoint is available. Post-cleanup file checks match both
tool witnesses, and log prefixes still match. No open files remain in either
owned fixture after the private daemons/tmux/controllers stop.

Project trust is reviewed through the native interactive CLI without a model
turn. Both disposable projects temporarily use workspace-write/on-request for
that review, then restore their final never-approval policy before managed
creation. Final project-config hashes, resolved plans and every coding context
verify the intended policy. The native updater is skipped if offered; neither
the qualified CLI version nor its trust guard changes.

Two earlier workspace preparations remain failed and excluded: native trust
readiness was unconfirmed in the first; an older browser observer watched the
legacy creation URL in the second. Its correction binds all observation and
duplicate/completion checks to the actual original creation-request URL. All
other recovery assertions remain. Their exact receipts and drivers are retained
by hash; no product failure is inferred from those setup attempts.

The completed read-only browser run passes all 16 controls, but its original
raw receipt is false because one copied offline assertion still expects
on-request approval. A separate source-bound audit corrects only that expectation
to require never and rechecks the same exact native history, correlated initial
and resumed tools, policy/model, original native ID and current source hashes.
It passes with no further coding turn or native launch. The original failed
receipt stays byte-identical; both checker versions and the audit are retained.
Codex's read-only journal omits default network_access:false, so verification
requires its exact recorded shape, the network-disabled native plan and actual
network-denial results.
